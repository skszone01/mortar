## `shell_physics_from_game.json`

ค่าที่ใช้ในโหมด "คำนวณขั้นสูง" ของเว็บ (คัดลอกไปอยู่ใน `script.js` แล้วในชื่อ `SHELL_PHYSICS`)

สมการที่เอนจิ้นเกมใช้จริง (จาก `ShellMoveComponent` + สคริปต์ `BallisticTable.c`):

| M819 (81mm Smoke) | 137 | 4.85 | 0.0009139 | 1.8843e-4 |

- ความเร็วต้นของแต่ละ ring ในไฟล์ JSON ปรับเทียบกับตารางที่เกม/mod แจกมาแล้ว **คลาดเคลื่อน ≤ 0.05%**

## `wind_data_vanilla_from_game.js`

> ✅ **นำไปใช้ในเว็บแล้ว** — `WIND_DATA` ใน `script.js` ตอนนี้คือชุดนี้ ไฟล์นี้เก็บไว้เป็นต้นฉบับสำรอง

ตารางค่าแก้ลมของกระสุน Original ที่สกัดจากไฟล์เกมโดยตรง
(`WindData_Shell_*.conf` ใน `data007.pak`) — รูปแบบเดียวกับ `WIND_DATA` ใน `script.js`
ใช้จุดระยะชุดเดียวกัน

> ⚠️ **ไฟล์นี้ล้าสมัยแล้ว** — มันถูกสร้างด้วยสคริปต์ที่จับคู่แถวผิด (ดูหัวข้อถัดไป)
> ค่าที่ใช้จริงใน `script.js` ตอนนี้เป็นชุดที่สร้างใหม่แล้ว เก็บไฟล์นี้ไว้เป็นบันทึกประวัติเท่านั้น

**เหตุผลที่แทนที่ของเดิม:** `WIND_DATA` ชุดเก่าคัดลอกมาจาก arma-mortar.com
ซึ่งคอลัมน์ Zw (ค่าแก้ทิศจากลมขวาง) สูงเกินจริงอย่างเป็นระบบ

| | คลาดเคลื่อนกลาง |
|---|---|
| Xw (ค่าแก้ระยะ) | 4.2% — ใช้ได้ |
| Zw (ค่าแก้ทิศ) | 22% — เพี้ยนมาก |

ยิ่ง ring สูงยิ่งเพี้ยน (ring 0 ≈ 1%, ring 4 ≈ 33%) และกระสุนส่องสว่างหนักสุด

## บันทึก: ตารางลมถูกแก้ 2 รอบ

**รอบที่ 1** — เปลี่ยนจากชุดที่ลอกมาจาก arma-mortar.com (Zw สูงเกินจริง) มาเป็นชุดที่สกัดจากไฟล์เกม

**รอบที่ 2** — พบว่าสคริปต์ที่ใช้ในรอบแรกจับคู่แถวผิด จึงสร้างใหม่ทั้งหมด

ในไฟล์ `WindData_Shell_*.conf` แต่ละประจุมีอาร์เรย์ 90 แถวสองชุด:
- `m_aFiringSolution[i]` = `[มุมยิง (เรเดียน), ระยะ (m), ความสูงสูงสุด (m)]`
- `m_aValues[i]` = `[ค่าแก้ทิศ (มิลลิเรเดียน), ค่าแก้ระยะ (m), **มุมตกกระทบ** (องศา)]`

สคริปต์รอบแรกไปไล่หาแถวใน `m_aValues` ที่คอลัมน์ *มุมตกกระทบ* ตรงกับ *มุมยิง* — ซึ่งผิด
เพราะมุมตกกระทบมากกว่ามุมยิงเสมอ (แรงต้านอากาศทำให้ขาลงชันกว่าขาขึ้น) จึงหยิบแถวที่ตื้นกว่ามาใช้

ซอร์สโค้ดเกม `SCR_ProjectileWindData.c` ยืนยันว่าต้องจับคู่ **ตามลำดับแถว**:

```c
vector fireSolutionOut = vector.Lerp(first, second, t);
vector valuesOut = vector.Lerp(m_aValues[midId-1], m_aValues[midId], t);
```

ใช้ `midId` และ `t` ตัวเดียวกันทั้งสองอาร์เรย์ คอลัมน์มุมตกกระทบเป็นแค่ข้อมูลผลลัพธ์ ไม่ใช่ดัชนี

ผลของการแก้: Zw เพิ่มขึ้น 3–94% (ยิ่ง ring สูงยิ่งเพิ่มมาก เพราะช่องว่างระหว่างมุมยิงกับมุมตกกว้างขึ้น)
กระสุนส่องสว่างที่แรงต้านอากาศสูงเพี้ยนหนักสุด — C-832C ring 4 ที่ 400 m: เดิม 217 → ใหม่ **440**
อีกจุดคือลืมแปลงหน่วยมิลลิเรเดียนเป็นมิล (NATO ×1.0186, รัสเซีย ×0.9549)

ชุดใหม่ตรวจสอบด้วยการจำลองวิถีกระสุนอิสระ 19 จุด ได้อัตราส่วนกลาง **1.000** ทั้ง Zw และ Xw

## หมายเหตุ: ค่าคูณประจุของ A-832AY ใน MOD มี 2 ชุดที่ไม่ตรงกัน

- `Ammo_Shell_82mm_Smoke_D832DU.et` (ตัวกระสุนที่เกมยิงจริง) ใช้ **2.423, 2.975**
- `AM_M_MortarBallisticTableGeneratorConfig_D832DU.conf` (ตัวสร้างตาราง) ใช้ **2.428, 2.981**

เว็บปรับเทียบตาม *ตัวสร้างตาราง* เพื่อให้ตรงกับตารางที่ผู้เล่นเห็นในเกม
ผลคือคลาดจากกระสุนจริงราว 0.2% ของความเร็ว (≈ 0.4% ของระยะ หรือ ~10 m ที่ 2.7 กม.)
เป็นความไม่ตรงกันภายในตัว mod เอง ไม่ใช่ข้อผิดพลาดของเว็บ

นอกจากนี้ mod นับ ring ของกระสุนนี้เป็น **0–3** (ตาม `m_aChargeRingConfig`) เหมือนกับของ Original
เว็บเคยใส่เป็น 1–4 ซึ่งผิด แก้แล้ว

## หมายเหตุสำคัญ: คอลัมน์ Hw ในตารางเกมไม่ใช่ค่าแก้ความสูงที่แท้จริง

จากสคริปต์ `SCR_VisualisedBallisticConfig.c` ของเกม คอลัมน์ Hw ถูกสร้างจาก

```
Hw = | มุมยกที่ระยะ (R + 50) − มุมยกที่ระยะ R |
```

เท่ากับ**สมมติว่ามุมตกกระทบคงที่ 63.4°** (คือแปลงความสูง 100 m เป็นระยะ 50 m เสมอ)
ทั้งที่มุมตกจริงในเกมอยู่ระหว่าง 64°–86° ค่าแก้จึงเพี้ยนมากเมื่อความสูงต่างกันเยอะ

ตัวเกมเองตอนยิงจริง**ไม่ได้ใช้ค่านี้** แต่จำลองวิถีใหม่ทั้งเส้น
(`BallisticTable.GetAimHeightOfProjectileAltitudeFromSource` — คอมเมนต์ในสคริปต์เขียนว่า
"This method simulates the projectile, so it takes considerable time to run!")

นี่คือเหตุผลที่เว็บเพิ่มโหมด "คำนวณขั้นสูง" เข้ามา
